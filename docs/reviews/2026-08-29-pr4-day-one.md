## Intent audit — does it redo/override existing work?

A second-pass audit examined every element against the pre-PR systems (160afde). **Verdict: the PR works *with* the existing architecture, not against it** — the strongest intent profile of the three open PRs:

- **Receipts REUSE the citation slip wholesale** — same `citationPanel`/`citationText`/`citationContinueButton`/dismiss flow; the change is one gating condition plus two small helpers. No parallel mechanism was built.
- **Where a no-code path existed, it was taken:** `Rule_NoEgyptDay1` is a plain `TravelRuleSO` asset on the existing system (the rule code is untouched); the OvertimePay fix uses the pre-existing `EffectSO` `PayRateBonus` op + `SlotOutcomeSO.effect`/duration fields — pure data.
- **Pinning is a real capability gap, extended in place:** at 160afde a forced slot pinned only the blueprint — era/name/birthdate/forgery were still random, so a scripted Day One was *not* expressible as assets alone. The gap is named and "flagged to director" in the plan (per the manifesto's reuse rule), the pin fields are optional, and every pre-existing `CaseFactory` path survives as the fallback. Bonus: the hardcoded birth-year `switch` was migrated into `EraSO` data with the old values preserved — removing a Law-3 defect.
- **The save rewire fixes a demonstrable bug in the old placement:** evening/end-of-shift saves held day N with day-N economy already applied, while Continue always reloads the office and regenerates day N → double-applied pay/citations/impacts; and `NewRun` never saved at all. The fix is 13 added lines, 2 removed calls, every deletion declared in FEATURES. Morning-boundary-only is strictly more consistent with Continue-always-loads-Office.
- **No hunk deletes pre-existing behaviour undeclared** (full hunk classification in the audit record).

Two intent-level cautions carried into the fix list: AGENTS.md restates manifesto rules in its own words (drift risk — it does explicitly defer, which mitigates), and the declared quit-during-Home data loss creates an undocumented slot-machine scum surface (spin, quit on a bad outcome, replay the day) — worth an explicit design decision on resubmission.

## Addendum — line-level redundancy audit (2026-08-29, second pass)

Method-by-method sweep against 160afde. Mandatory replacements on resubmission
(**use our code, don't re-implement it**):

1. **Two identical Gregorian month tables ship:** `CalendarConverter.GregorianMonths` vs `CaseFactory.Months` (branch CaseFactory.cs:472 — the baseline table, retained). Delete the CaseFactory copy; use the converter's.
2. **Date grammar lives in two homes.** The PR unified the calendar *data* on `EraSO` (good), but `ForgeBirthDate` (CaseFactory.cs:506–509) still hand-parses `"day month year"` with `Split` while `CalendarConverter.TryParse` owns the same grammar, and the layout string is composed inline at CaseFactory.cs:500. If the grammar ever changes, the generator writes dates the converter can't read. Fix: `ForgeBirthDate` calls `CalendarConverter.TryParse`; add `CalendarConverter.FormatDocumentDate(...)` and use it at the generation site. One grammar, one home.
3. **`DayOneValidation.FindEra` re-implements `ContentLibrarySO.GetEraById`** (dictionary-backed, ContentLibrarySO.cs:158). Delete; call ours. Same for **`DayOneFullDaySimulation.FindUpgrade`** vs `GetUpgradeById` (ContentLibrarySO.cs:171).
4. **`ToPairs`/`Pairs` iterator now exists three times** (TimelineRankedSprite.cs:189 + both editor tools). Add one Domain overload (e.g. `ScoreRanking.TryGetTop(List<ScoreEntry>, ...)`) and call it everywhere.
